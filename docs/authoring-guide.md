# 글 작성 · 분류 가이드 (Authoring & Taxonomy Guide)

> 이 문서는 `_config.yml`의 `exclude:`에 따라 사이트 빌드에서 제외된다. 공개 GitHub 저장소에서는 읽을 수 있으므로 내부 경로·원자료를 넣지 않는다.

---

## 1. 원칙과 범위

- **목적:** 업과 프로젝트에서 직접 확인한 설계 판단·트레이드오프·실패 조건을 담백하게 기록해 같은 문제로 막힌 독자를 돕는다.
- **복리 기준:** 버전이 바뀌어도 남는 원리와 트레이드오프를 쓴다. 버전 의존 셋업 나열, 뉴스 코멘터리, 기밀·고유 식별자, 미검증 주장은 제외한다.
- **사이트 정체성:** `JAEYEONG's BLOG` — *Backend Notes: State Mismatch · Duplicate Processing · Partial Failure*.

---

## 2. 카테고리 (대분류 5개 고정)

Chirpy에서 `categories: [A, B]`는 계층 구조다. **첫 자리에 아래 5개 대분류 중 정확히 하나**를 두고, 교차 주제는 태그로 연결한다.

| 카테고리 | 범위 |
| --- | --- |
| **분산시스템** | 상태 정합성, 멱등성, 정확 1회 처리, 합의, 관측성, 장애 복구 및 대사 |
| **신뢰성** | 도메인을 횡단하는 신뢰성 원리 자체(감사 추적, 결정적 재현, 기록 무결성, 실패 모드) |
| **인공지능** | AI·에이전트 오케스트레이션, 평가 게이트, LLM/ML 파이프라인 신뢰성 |
| **로봇** | 자율주행·로보틱스(RoboRacer 등) 설계·실험 노트 및 제어 루프 |
| **학습기록** | 도서·새 스택·도구를 익히며 직접 검증한 원리와 실험 기록 |

---

## 3. 태그 (소분류) 컨벤션

- **형식:** 영어 소문자 `kebab-case`, 글당 **3~5개**.
- 인물·회사·내부 시스템명은 태그로 쓰지 않는다.

| 태그 | 의미 |
| --- | --- |
| `reliability` | 신뢰성 속성 |
| `idempotency` | 멱등성 |
| `exactly-once` | 정확 1회 전달/처리 |
| `state-reconciliation` | 상태 정합성·대사 |
| `observability` | 관측성·로깅·추적 |
| `consensus` | 합의·리더 선출·fencing/lease |
| `control-plane` | 컨트롤 플레인 설계 |
| `audit-log` | 감사 로그·기록 무결성 |
| `deterministic-replay` | 결정적 재현 |
| `fleet` | 로봇/에이전트 fleet |
| `vda5050` | VDA5050 프로토콜 |
| `multi-agent` | 다중 에이전트 오케스트레이션 |
| `golang` | Go 언어 |
| `concurrency` | 동시성 |
| `meta` | 블로그 운영·공지 |

## 4. Front Matter 및 본문 규약

```yaml
---
title: 글 제목 (한국어, 담백하게)
description: 글 핵심 요약 (한국어 60~100자 내외, 검색 결과 스니펫용)
date: 2026-10-20 09:00:00 +0900   # KST(+0900). 미래 날짜면 발행 안 됨
categories: [분산시스템]            # §2의 5개 중 하나
tags: [state-reconciliation, idempotency, reliability] # §3에서 3~5개
toc: true
pin: false
---
```

- **본문 전개:** `상황(무엇을 맡았나) ➔ 사건(예상과 달리 무엇이 깨졌나) ➔ 원인(어디가 문제였나) ➔ 설계 결정(대안 비교·채택·기각 이유) ➔ 결과 및 잔여 위험`.
- **문체:** 교과서식 도입부와 훈장 톤 결론을 배제하고, 짧은 단문과 사실 중심으로 서술한다.
- **영문 요약:** 글 하단에 `## English Summary` 블록(3~5문장)을 둔다.

## 5. 발행 게이트 체크리스트

원고 보관·미리보기·승인·반영은 [저장소 작성 절차](../README.md#writing)를 따른다.

- [ ] **소유권:** 결론과 트레이드오프를 직접 판단·검증했고 한계를 설명할 수 있는가
- [ ] **기밀 제거:** 내부 시스템명·고객·사내 티켓 ID·정확 비율·내부 경로를 제거하고 일반화했는가
- [ ] **과장 금지:** 완료·검증한 사실만 단정하고 미완성·AI 구현 경계를 명확히 구분했는가
- [ ] **분류·형식:** 요약(`description`), 카테고리 1개(§2), 태그 3~5개(§3), 과거/현재 `date`, 하단 영문 요약을 포함했는가
- [ ] **검증 통과:** `bash tools/test.sh` 빌드 및 내부 링크 검사를 통과했는가
